<tr class="even">
<td colspan="6"><p>This draft new Technical Specification specifies the concepts, security framework, security risks, security requirements, and main procedures and methodologies for trusted environment measurement and attestation for Artificial Intelligence (AI) agents.</p>
<p>The scope of this draft new Technical Specification includes:</p>
<p>- Concepts of trusted environment measurement and attestation for AI agents;</p>
<p>- Security framework, including relevant systems, functional entities and equipment;</p>
<p>- Security risks in trusted environment measurement and attestation for AI agents;</p>
<p>- Security requirements for trusted environment measurement and attestation;</p>
<p>- Main procedures and methodologies for environment measurement, attestation and dynamic trust decisions.</p>
<p>The appendixes provide use cases and a reference data model for environment measurement.</p></td>
</tr>

<td colspan="6">Summary (summarizes the purpose and contents of the Recommendation so readers can decide whether it helps their work):</td>
</tr>
<tr class="even">
<td colspan="6"><p>Artificial Intelligence (AI) agents increasingly run outside static environments on distributed platforms such as cloud data centers, edge nodes, mobile devices and IoT endpoints. Existing AI agent security standards check identity and authorization, but fail to verify runtime platform integrity. An agent on a compromised platform is untrustworthy even with valid credentials. Trusted Execution Environment adoption remains fragmented across different hardware architectures using proprietary attestation formats. Systems lack standardized ways to measure, attest or verify platform integrity. This gap leaves networks vulnerable to measurement tampering, attestation forgery, replay attacks and stale attestations. Access control models lack standardized environment measurement inputs for dynamic authorization. Emerging regulations require verifiable evidence of platform integrity. Environment measurement and attestation acts as the hardware root of trust for identity and authorization frameworks.</p>
<p>This draft new Technical Specification adds the missing environment dimension to complete the who-what-where trust triad, enables cross-platform interoperability and supports dynamic, risk-based trust decisions. The scope covers security risks, security requirements and methodologies for trusted environment measurement and attestation of AI agents.</p></td>
</tr>
